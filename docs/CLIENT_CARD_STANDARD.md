# Единый стандарт зеркал клиента — все каналы

> **Это spec.** Все 5 каналов (WA, TG-shard, MAX, TG-боты, Instagram Direct/Comments)
> **обязаны** соответствовать ВСЕМ пунктам ниже. Любое отклонение — это
> регрессия, фиксируется в [`REGRESSIONS.md`](./REGRESSIONS.md).
>
> Если канал-имплементация не покрывает все пункты — это **не «частично работает»**,
> это **не работает по стандарту**. Не выкатывать в прод.

## 1. Заголовок форум-темы (forum_topic name)

Формат:
```
<CHANNEL> · <SOURCE> · <CLIENT_NAME>
```

| Канал | CHANNEL | SOURCE | Пример |
|---|---|---|---|
| WhatsApp | `WA` | shard label (3354 / 8566 / …) | `WA · 3354 · Иван Петров` |
| Telegram (Green API shard) | `TG` | shard label | `TG · 3354 · Анна` |
| MAX | `MAX` | shard label | `MAX · 3354 · +79055994431` |
| TG-бот @begovoy_bot | `TG` | `begovoy_bot` | `TG · begovoy_bot · Olga K` |
| TG-бот @begovoy1support_bot | `TG` | `support_bot` | `TG · support_bot · Иван` |
| Instagram Direct | `IG-Direct` | `@<ig_username>` или `IG` | `IG-Direct · @anna_p · Анна П.` |
| Instagram Comments | `IG-Comments` | `пост #<media_id_short>` | `IG-Comments · пост #abc123 · Олег П.` |

**CLIENT_NAME** — резолв в порядке приоритета:
1. ФИО из B24 (по UF_CRM_*_CHAT_ID / phone / username)
2. Имя из мессенджера (Bot API `from.first_name + last_name`, Green API `senderName`)
3. Phone / username fallback (`+79…`, `@username`)

**Лимит**: Telegram forum_topic name ≤ 128 символов. Если общая длина >128 —
обрезать CLIENT_NAME (по символам, с `…` суффиксом).

## 2. Pinned карточка (закреплённое сообщение в начале темы)

Структура — **строго в этом порядке**:

```
📋 Карточка клиента (<канал>)

[фото клиента, если есть]               ← как media-сообщение, не текст

Имя: <ФИО из B24>                       (только если известно)
<Канал>: <идентификатор>
Линия: <человеческое название>
B24 лид: <https://1begovoy.bitrix24.ru/crm/lead/details/<id>/>     (если есть открытый)
B24 контакт: <https://1begovoy.bitrix24.ru/crm/contact/details/<id>/>  (если есть)
B24 сделка: <https://1begovoy.bitrix24.ru/crm/deal/details/<id>/>     (если есть открытая)
Customer-360: <uuid>                    (всегда — find-or-create)
Команды: /nnn <текст> — внутренняя заметка
```

**Обязательные строки**:
- `📋 Карточка клиента (<канал>)` — заголовок с указанием канала
- `<Канал>: <идентификатор>` — phone / @username / chat_id (что есть)
- `Линия: <название>` — человеческое (не `instance#1`)
- `Customer-360: <uuid>` — всегда
- `Команды:` — справка

**Опциональные**:
- `Имя:` — пропустить если ФИО не известно
- Фото — пропустить если нет (best-effort через канал-API)
- B24 ссылки — пропустить если нет соответствующей сущности

## 3. Подпись каждого сообщения **оператора** (исходящие)

Формат заголовка сообщения от оператора:
```
👤 <ФИО оператора>:
<текст>
```

**ОБЯЗАТЕЛЬНО**: конкретное `ФИО оператора` (NAME + LAST_NAME из B24), НЕ
просто `оператор (B24)` маской.

Способы получить ФИО:
1. Из B24 imopenlines.session — поле `OPERATOR_ID` → `user.get` → `NAME LAST_NAME`
2. Кэш `b24UserNames` в `bitrix24.service.ts` (уже есть)
3. Fallback: `оператор (B24) #<id>` если резолв не сработал

## 4. Подпись каждого сообщения **клиента** (входящие)

Формат:
```
👤 <Имя клиента>:
<текст>
```

`Имя клиента` — то же что в заголовке темы (B24 ФИО > messenger name > fallback).

## 5. Системные/служебные сообщения

Префикс `⚙️` + краткое описание:
- `⚙️ диалог завершён <operator-name>`
- `⚙️ сменил аватар`
- `⚙️ канал переключён`
- и т.п.

## 6. Backfill старых тем

При деплое спецификации:
1. Перепинить карточки старых тем (rate-limit 1 op / 1.5 sec — TG Bot API)
2. Переименовать заголовки старых тем через `editForumTopic(name=...)`
3. Старые сообщения **не переписываем** — только новые получают новые подписи

Bridge: `POST /internal/refresh-pinned-cards` (уже есть, расширяется этим стандартом)
Adapter (TG-bot mirror, IG-mirror): новые endpoints `/internal/refresh-tg-bot-topics`,
`/internal/refresh-ig-topics`.

## 7. Чек-лист на канал перед merge

Для **каждого** канала (WA / TG-shard / MAX / TG-boты / IG):

- [ ] Заголовок темы по формату (1)
- [ ] Pinned карточка по структуре (2)
- [ ] Фото клиента в карточке если есть
- [ ] Подпись оператора с ФИО (3) — не просто `оператор (B24)`
- [ ] Подпись клиента с именем (4)
- [ ] Smoke на новой теме — все ОК
- [ ] Refresh-endpoint для backfill старых тем

**Если хотя бы один пункт не выполнен на каком-то канале** — релиз не катить.
Лучше потратить день на полноту, чем 10 раз чинить одно и то же.

## 8. История регрессий «карточка не унифицирована»

Записывать в [`REGRESSIONS.md`](./REGRESSIONS.md). Каждое появление проблемы
вида:
- «нет фото клиента»
- «не понятно через какой бот»
- «нет ФИО оператора»
- «есть в одном канале, нет в другом»

— это регрессия (или невнедрение этого стандарта). Не молчать.
