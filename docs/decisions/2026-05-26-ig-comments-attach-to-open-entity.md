# ADR 2026-05-26: IG Comments прицепляются к открытой сущности B24

## Контекст

До этого ADR действовало правило A2: «один (клиент × пост) = одна сессия
= один лид». При комментировании клиентом 5 разных постов создавалось
5 разных лидов, связанных с одним контактом через `UF_CRM_IG_CHAT_ID`.

Дмитрий 2026-05-26 пересмотрел правило: лишних лидов плодить не нужно.
Если у клиента уже есть открытая сделка или лид — все комменты должны
идти туда.

## Новое правило

**Приоритет — открытая сущность B24 у клиента.** Иерархия:

1. У клиента есть **открытая сделка** → коммент идёт в **эту сделку**
2. Открытой сделки нет, но есть **открытый лид** → коммент идёт в **этот лид**
3. Ни открытой сделки, ни лида → создаётся **новый лид**

Применяется:
- К **любому каналу IG** (Direct и Comments) — не зависит от линии
- К **любому посту** — новый пост ≠ новый лид
- По **контакту в B24** (по `UF_CRM_IG_CHAT_ID` или phone) — не по chat.id

То же поведение для **outgoing IG Direct из существующего лида/сделки**:
не создавать новый лид, открыть линию в рамках текущей сущности.

## Что считать «открытым»

**Лид** — STATUS_ID не в {`CONVERTED`, `JUNK`} (любой `NEW`/`IN_PROGRESS`/
`PROCESSED`/etc. = открыт).

**Сделка** — `STAGE_ID` не в финальных стадиях (`WON`, `LOSE`). Стадии
«в работе»/«ожидает оплаты»/etc. = открыта.

Точный список финальных стадий — в B24 настройках портала, нужно
зафиксировать при реализации.

### Изменение chat.id

Старый формат: `i2crm_ig_<client>_c<media>` (A2)
Новый формат: `i2crm_ig_<client>` (одинаковый для всех постов и Direct)

Этап миграции:
- Текущие сессии с A2 chat.id остаются (B24 их не удалит)
- Новые комменты — с новым chat.id
- Постепенно старые сессии закроются (24ч без активности)

### Где найти открытую сущность

`crm.lead.list` с фильтром:
```
filter: {
  UF_CRM_IG_CHAT_ID: <clientId>,
  "!STATUS_SEMANTIC_ID": ["F", "S"]  // F=finished, S=successful — закрытые
}
```

Аналогично `crm.deal.list` с фильтром по `STAGE_SEMANTIC_ID` (открытые
сделки: P=process).

## Ответы Дмитрия 2026-05-26

После уточнений в чате (см. session log):

1. **Сделка автоматически НЕ создаётся** — только менеджер вручную
   конвертирует из лида когда есть смысл. Из правила убран кейс
   «новая сделка», остался только «новый лид».

2. **Каждый новый пост = отдельная новая открытая линия в линии 22**,
   прикреплённая к существующему лиду (если он есть) или к контакту
   (если открыта сделка). **Лиды дополнительные НЕ плодим.**

3. **Если у клиента 2+ открытых сделок** — коммент дублируется в
   timeline **во все** одновременно. Не выбираем «самую свежую» —
   менеджеры сами разберутся.

4. **`!`-префикс из Comment-чата** создаёт **новую Direct-сессию в
   линии 18**, прикреплённую к тому же лиду/контакту. Сессия сразу **в
   работе у этого менеджера** (auto-take), без попадания в нераспределённые.
   Если менеджер не отвечает 10 мин — auto-release возвращает в общую
   очередь (общее правило SLA_RULES.md).

5. **Линия 22 остаётся**. Холодные клиенты (без открытых сущностей)
   проходят через неё нормально — там и создаётся первый лид.

6. **Comments автоматический ответ оператора** работает через виджет
   Social Connector / Open Line чат **новой сессии того поста**.
   Timeline-комментарий идёт **параллельно** для информации других
   сделок (если у клиента сделка) — это уведомительный канал, не
   рабочий.
