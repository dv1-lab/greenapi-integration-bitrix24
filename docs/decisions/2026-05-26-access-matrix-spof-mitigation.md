# 2026-05-26 — Single point of failure: только у Дмитрия есть доступ

## Контекст

Все критичные системы (Bitwarden master, my-server SSH, B24 admin,
MoySklad, GitHub, Cloudflare, банк, etc) доступны **только Дмитрию**.
Никаких backup-человек не назначено.

**Риск-сценарии:**
- Дмитрий заболел/в отпуске и недоступен > 1 неделя
- Дмитрий потерял мак (украли, утопил, разбил) — нужен немедленный
  доступ для recovery
- Дмитрий проебал Master pwd Bitwarden — все остальные секреты
  становятся недоступны
- Хуже сценарий — что-то серьёзное с Дмитрием

В **любом** из этих сценариев платформа не сможет функционировать:
- Никто не рестартанет упавший сервис
- Никто не ротирует утёкший токен
- Никто не отвечает на B24 webhook'и (заглохнет CRM)
- Никто не оплатит подписки (Green API, Bitwarden, hip.hosting),
  они отвалятся через ~30 дней

## Решение (предложение, требует согласования Дмитрия)

### Шаг 1. Назначить **backup-person**

Кандидаты:
- **Член семьи** (жена, родители, брат/сестра) — если tech-savvy
- **Доверенный сотрудник** (Анастасия?) — но операторам обычно не дают
  admin-доступ
- **IT-консультант на ретейнере** (отдельный человек, NDA, на телефоне
  при инциденте)
- **Партнёр по бизнесу** (если есть)

Backup-person **не должен** видеть текущие секреты в нормальном режиме
— только при наступлении триггера (Дмитрий 7+ дней не отвечает).

### Шаг 2. Bitwarden Emergency Access (премиум feature)

Bitwarden поддерживает **Emergency Access**:
1. Дмитрий приглашает backup-person в Bitwarden как Emergency Contact
2. Указывает **grace period** (рекомендую 7 дней)
3. Если backup-person запрашивает доступ — Дмитрий получает
   уведомление, может **отказать** в течение grace period
4. Если Дмитрий не отвечает 7 дней — backup-person получает доступ
   автоматически

Стоимость Bitwarden Premium: ~$10/год. Уже оплачено?

### Шаг 3. Physical backup — sealed envelope

В банковской ячейке (или у нотариуса):
- Master pwd Bitwarden
- 2FA recovery codes (для всех 2FA-enabled аккаунтов)
- SSH private keys (printout QR-codes или paper-key)
- Список ключевых аккаунтов с paroles

Это **резервный** канал на случай если Bitwarden становится недоступен.

### Шаг 4. Тест раз в полгода

«Drill» — симулировать что Дмитрий недоступен 1 день, проверить что
backup-person:
- Может войти в Bitwarden (через Emergency Access или ячейку)
- Может зайти на my-server (SSH-ключ)
- Может рестартануть один сервис по runbook
- Знает где лежит документация (этот репо)

## Альтернативы (отвергнуты)

| Вариант | Почему отвергнут |
|---|---|
| Дать backup-person **прямой** доступ ко всему сейчас | Расширяет attack surface постоянно (а не только при инциденте) |
| Использовать password manager с **multi-user vault** (1Password Teams) | Дороже Bitwarden Emergency Access, overkill для 2 человек |
| Только sealed envelope, без Emergency Access | Если envelope недоступен (банк закрыт, ключ потерян) — single point of failure физический |
| Распределить доступы по нескольким людям (например, Bitwarden у одного, SSH у другого) | Сложнее координация при инциденте; backup-person всё равно нужен на critical recovery |

## Последствия

**Положительные:**
- Платформа выживет при недоступности Дмитрия 1+ недель
- Снижается тревога Дмитрия (не нужно «всё всегда сам»)
- Возможность реального отпуска без 24/7 on-call

**Подвохи / надо мониторить:**
- Backup-person должен быть **технически грамотен** (читать
  runbooks, ssh, docker)
- Backup-person должен быть **доверенным** — он получит ключи от
  всего бизнеса
- Раз в год обновлять Bitwarden Emergency Access (проверить что
  контакт ещё актуален)
- Раз в полгода — drill-тест

## Решения Дмитрия (26.05.2026)

| Вопрос | Решение |
|---|---|
| **Кого назначить backup-person?** | Член семьи (жена / родители / брат) — конкретное имя TODO |
| **Механизм передачи** | Bitwarden Emergency Access (без sealed envelope) |
| **Bitwarden Premium** | НЕТ, нужно купить (~$10/год) |

**Минус выбора без sealed envelope:** если Bitwarden как сервис
окажется недоступен (компания закрылась, акк заблокирован) — есть
риск потери всего. Sealed envelope страховал бы. Но Дмитрий принял
этот риск (Bitwarden — крупный игрок, риск низкий).
