# 2026-05-26 — Выключили CRM_CREATE_SECOND для всех open-lines

## Контекст

Когда известный клиент (контакт уже есть в B24) пишет повторно — B24
автоматически создавал **новый лид «Повторный лид»**. Это происходило
с настройкой `CRM_CREATE_SECOND="0"` на 7 линиях (WA/MAX/TG/IG):

- Клиент пишет первый раз → лид (норма)
- Клиент пишет второй раз → ещё один лид «Повторный лид»
- Клиент пишет третий раз → ещё лид

Дубли:
- Ломали CRM-метрики «новые лиды в неделю» (false-positive)
- Засоряли список лидов для операторов
- Не было «единого места» переписки с клиентом

Дмитрий повторял это правило **несколько сессий** устно, но нигде не
было зафиксировано → каждая сессия начиналась с «почему создался лид?».

## Решение

Для **всех** open-line линий установить:

```
PARAMS[CRM_CREATE]       = lead    # при первом обращении — лид (как было)
PARAMS[CRM_CREATE_SECOND] = N       # повторный лид НЕ создавать
PARAMS[CRM_FORWARD]      = Y       # forward в открытую сделку если есть
```

Это даёт правило:

| Состояние контакта | Action |
|---|---|
| Открытая сделка | Переписка в неё. Лид не создаём |
| Открытый лид (нет сделки) | Переписка в текущий лид. Новый не создаём |
| Ни сделки ни лида открытого | Создаём новый лид |

## Альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Оставить как было (CRM_CREATE_SECOND="0") | B24 трактует "0" как truthy, плодит дубли |
| `CRM_CREATE = none` | Тогда вообще не создаются лиды для **новых** клиентов — теряем точку входа CRM |
| `CRM_CREATE = deal` (минуя лид-стадию) | Дмитрий хочет квалификацию через лид для новых клиентов |
| Кастомный код в adapter | Лишняя сложность. B24 умеет нативно через config |

## Последствия

**Положительные:**
- Один лид на одно намерение клиента
- Переписка собрана в одном месте (сделка или текущий лид)
- CRM-метрики «новых лидов» отражают реальность

**Подвохи / надо мониторить:**
- `CRM_CREATE_SECOND="0"` (строка) — НЕ работает, нужно строго `"N"`
- При создании **новой** open-line линии (например когда добавим новый WA-номер)
  — обязательно сразу применить эту настройку. Иначе B24 заведёт
  дефолт и дубли вернутся для этого канала.
- Customer-360 merge engine остаётся важным — если по какой-то причине
  у клиента всё-таки два UUID, нужно их объединить (см. PRODUCT_RULES §1.2)
