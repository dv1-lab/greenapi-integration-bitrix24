# Onboarding для Backup-person

**Этот документ — для человека которого Дмитрий назначил backup'ом**
на случай если с ним что-то случится и платформа «Первый Беговой»
нуждается в emergency-восстановлении.

Если ты читаешь это — значит ты согласился стать backup-person. Спасибо.

---

## ⚠️ Когда вступать в роль

**НЕ вступай** если:
- Дмитрий просто не отвечает 2-3 дня (отпуск, нет сети)
- Платформа работает (клиенты получают ответы, операторы видят чаты)

**Вступай** если **ОБА** условия выполнены:
1. Дмитрий не отвечает **> 7 дней** (или его жена сказала «что-то случилось»)
2. **И** какая-то часть платформы сломана / нужно ротировать секрет
   / нужно ответить на критический инцидент

---

## Что у тебя есть

### Bitwarden Emergency Access

Дмитрий назначил тебя как Emergency Contact в Bitwarden. Процедура:

1. Зайди в `https://bitwarden.com` со своего аккаунта
2. Settings → Emergency Access → найди приглашение от Дмитрия
3. Нажми «Request Access»
4. Подожди **7 дней** (grace period) — Дмитрию приходят уведомления,
   он может **отказать** в течение этого срока. Если он реально
   недоступен — отказ не придёт.
5. Через 7 дней — получишь доступ к **всему** vault Дмитрия

После этого все секреты (SSH-ключи, пароли admin-аккаунтов, API
токены) — у тебя в Bitwarden.

## Что ты должен знать про платформу

### Архитектура (5 минут чтения)

`https://github.com/dv1-lab/greenapi-integration-bitrix24/blob/main/docs/SOCIAL_CONNECTOR.md`

TL;DR: Bitrix24 CRM ↔ Adapter (наш NestJS) ↔ Каналы (WhatsApp/Telegram/Instagram).
Клиенты пишут с разных каналов — всё попадает в CRM Дмитрия как
лиды/сделки. Операторы (Анастасия / Кирилл / Олег) отвечают через
Bitrix24 — клиенты получают ответы обратно в свой канал.

### Главные сервисы (что не должно умереть)

1. **adapter** на my-server (Docker, NestJS) — без него каналы не работают
2. **wa-tg-bridge** на my-server (systemd Python) — зеркало в TG для операторов
3. **dv-dashboard** на dashboard.9wb.ru — BI, не критично если упадёт
4. **customer-service** на my-server (Postgres+CH) — клиентская база

### Главные операторы

- **Анастасия Василенко** — старший оператор, отвечает в B24
- **Кирилл / Олег** — также операторы

Если что-то не работает — они первыми скажут.

## Что ты можешь сделать (в порядке вероятности)

### 1. Перезапустить сервис

90% инцидентов решаются рестартом. См.
`https://github.com/dv1-lab/greenapi-integration-bitrix24/blob/main/docs/RUNBOOKS/restart-frozen-line.md`

Команды (потребуется SSH-ключ из Bitwarden):

```bash
# Где-то с компьютера (mac/Linux)
ssh my-server "
  sudo systemctl restart wa-tg-bridge
  cd /home/dv/greenapi-b24 && docker compose restart
"
```

### 2. Деплой откатить (если что-то сломалось из-за нового кода)

```bash
ssh my-server "
  cd /home/dv/greenapi-b24/source && git log --oneline -5
  # выбрать sha когда работало
  git reset --hard <prev_sha>
  cd .. && docker compose up -d adapter --build --force-recreate
"
```

### 3. Ротировать утёкший секрет

См. `https://github.com/dv1-lab/greenapi-integration-bitrix24/blob/main/docs/RUNBOOKS/rotate-greenapi-token.md`

### 4. Восстановить из бэкапа если сервер сдох

См. `https://github.com/dv1-lab/greenapi-integration-bitrix24/blob/main/docs/SERVICE_BLUEPRINT.md`

Бэкапы лежат на Я.Диск Дмитрия (через restic, ежедневно 04:00 МСК).
Доступ — в Bitwarden запись «Yandex.Disk Дмитрия».

## Что НЕ нужно делать

### Не паниковать

Если что-то сломалось — у нас есть документация, runbooks, бэкапы.
Все сценарии описаны.

### Не пытаться писать код

Если ты не разработчик — **не правь код**. Просто рестартуй или
откатывай через `git reset --hard`. Если нужно реально программировать
— найми разработчика (Дмитрий хранил контакты в Bitwarden).

### Не общаться с клиентами напрямую без подготовки

Если нужно — координируйся с Анастасией. Она знает текущий стиль
ответов.

### Не закрывать бизнес без необходимости

Если временный простой 1-2 дня — это OK. Бизнес выдерживает.
**НЕ** объявлять закрытие без уверенности что Дмитрия нет.

## Финальная инструкция

Если ситуация **критическая** (Дмитрий точно не вернётся в обозримое
время) — **не делай резких движений**:

1. Заморозь все нестратегические операции
2. Поддерживай платформу в рабочем состоянии (рестарты, оплата подписок)
3. Свяжись с **семьёй Дмитрия** (если ты не семья) для координации
4. Если бизнес продолжается — найми тех-консультанта на ретейнере для
   развития (в Bitwarden есть контакты)
5. Если бизнес закрывается — корректно сообщи клиентам, отдай данные
   через export

Берегите платформу. Спасибо.
